| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| **F**   | **Функциональные (Functionality)**     |              |
| F1 | Пользователь видит все доступные продукты на сайте с актуальной инф-ей  на сайте и ИБ  |     |
|  F2   | Возможность СМС информирования  |              |
| F3  | Более гибкая работа со ставками для сотрудников отделов кредитов и депозитов. (Перенос ф-ий из EXCEL в АБС)      |              |
| F4 | Перенос процессов согласования в АБС  |              |
| F5 | Возможность подачи заявки на кредит на сайте |              |
| F6 | В ИБ переодически должен происходить скоринг клиента, результат должен предлагаться клиенту |              |
| F7 | Необходимо использовать цвета банка |              |
| F8 | Использование механизма шифрования трафика протоколом TLS 1.2+   |  Для сайта и ИБ  |
| F9 | Критические операции требуют СМС подтверждений  |              |
| **U**   | **Удобство использования (Usability)** |              |
| U1 | Менеджер сам звонит клиенту и подготавливает данные           |              |
| U2 | Возможность подачи заявки на кредит на сайте |
| U3  | СМС информирование  |              |
| U4 | Сотрудник отделения должен иметь возможность работать с предодобренной заявкой на кредит |              |
| U5 | СМС информирование по всем статутсам |              |
| **R**   | **Надёжность (Reliability)**    |              |
| R1 | Достпуность сервисов 24/7 и доступность 99.9 |              |
| R2  | Интернет-банк должен работать на двух нодах в разных ЦОДах и быть защищен от сбоев одного ЦОД |              |
| R3 | Необходимость резервного копирования  | Обязательная вещь всех критических систем |
| R4 | RTO (Время восстановления системы) 30 минут||
| R5 | RPO (Время восстановления системы) 15 минут||
| **P**   | **Производительность (Performance)**   |              |
| P1 | Отклик системы должен занимать не более 400мс  |              |
| P3 | Необходимость кэширования справочных данных |              |
| P4 | Для ускорения скоринга по новым клиентам необходимо кэшировать данные бюро кредитных историй |              |
| **S**   | **Поддерживаемость (Supportability)**  |              |
| S1 | Возможные новые техн-гии должны быть совместимы с существующими  |              |
| S2 | В банке должны быть спец-ты которые могут поддерживать исп. техн-гии                                |              |
| S3 | Предусмотреть обязательное ведение док-ии, и включение это в процесс проектирования-разработки вцелом   |              |
| **+R**  | **+ Ограничения (Restrictions)**       |              |
| +R1 | Использование MS Sql и Oracle |              |
| +R2 | При необходимости асинхронности использовать Kafka |              |
| +R3 | Микросервисную арх. использовать только в ф-ле открытия депозитов        |              |
| +R5 | Избегать прямой работы интернет банка с АБС |              |
| +R6 | АБС масштабируется только вертикально изза БД |              |
| +R7 | Заявки из АБ в КК могут передаваться только раз в сутки |              |
| +R8 | Предрасчет кредита не должн на прямую обращаться в скоринг систему |              |
